# Vocab Forge · LexiTable

Веб-приложение для изучения слов: создавайте словари, редактируйте таблицы и повторяйте слова с помощью карточек.

Этот репозиторий содержит фронтенд. API находится в [vocab-forge-back](https://github.com/killursxlf/vocab-forge-back).

## Возможности

- Наборы слов с переводами, дополнительными столбцами, поиском и фильтрами.
- Статусы изучения: новое слово, изучается, изучено.
- Настройка сторон карточки, подсказки и выбор слов для тренировки.
- Тренировка с кнопками, свайпами и управлением с клавиатуры.
- Локальное сохранение ответов и фоновая синхронизация с сервером.
- Регистрация, вход по email или через Google, управление профилем.
- Русский и английский языки, светлая и тёмная темы.

## Технологии

React 18, TypeScript, Vite 8, Tailwind CSS 4, shadcn/ui и Radix UI, TanStack Query, Axios, i18next.

## Требования

- Node.js **22.12+**.
- Bun **1.4.0**.
- Запущенный API из репозитория бэкенда.
- Современный браузер: Chrome 111+, Safari 16.4+ или Firefox 128+.
- Chrome для браузерных тестов.

## Быстрый старт

### 1. Установите зависимости

```sh
git clone https://github.com/killursxlf/vocab-forge-front.git
cd vocab-forge-front
bun install --frozen-lockfile
```

### 2. Настройте окружение

Скопируйте `.env.example` в `.env.local`:

```dotenv
VITE_API_BASE_URL=http://localhost:3000
```

| Переменная | Назначение | Значение для разработки |
| --- | --- | --- |
| `VITE_API_BASE_URL` | Базовый URL API, включая префикс пути, если он используется | `http://localhost:3000` |

В разработке без этой переменной используется локальный API. Для сборки переменная обязательна. Google-вход использует тот же URL.

Переменные `VITE_*` доступны в браузере. Секреты и пароли должны храниться на бэкенде.

### 3. Запустите приложение

Запустите API отдельно, затем выполните:

```sh
bun run dev
```

Откройте [http://localhost:8080](http://localhost:8080).

## Команды

| Команда | Назначение |
| --- | --- |
| `bun run dev` | Сервер разработки |
| `bun run typecheck` | Проверка типов приложения и конфигурации |
| `bun run lint` | Проверка ESLint |
| `bun run test` | Модульные тесты |
| `bun run check` | Проверка типов, ESLint и модульные тесты |
| `bun run test:browser` | Браузерные проверки собранного приложения |
| `bun audit` | Проверка уязвимостей зависимостей |
| `bun run build` | Продакшен-сборка в `dist` |
| `bun run build:dev` | Сборка с окружением разработки |
| `bun run preview` | Локальный просмотр сборки |

Для браузерных проверок сначала соберите приложение с `VITE_API_BASE_URL=http://localhost:3000`. Тесты запускают Chrome и подставляют тестовый API, поэтому реальный бэкенд для них не нужен. Если Chrome установлен нестандартно, задайте путь к исполняемому файлу через `CHROME_PATH`.

GitHub Actions запускает проверки, аудит зависимостей, сборку и браузерные тесты при push и pull request.

## Сборка и размещение

Перед сборкой укажите адрес рабочего API в `.env.local` или окружении CI:

```dotenv
VITE_API_BASE_URL=https://api.example.com
```

```sh
bun run check
bun run build
bun run preview
```

Размещайте содержимое `dist` на статическом хостинге. Для маршрутов приложения настройте возврат `index.html`. URL API встраивается при сборке; при его изменении приложение нужно пересобрать.

На бэкенде должны быть настроены CORS с разрешённым origin фронтенда и `credentials: true`, cookie и Google OAuth. Для размещения используйте HTTPS: локальная очередь ответов требует безопасного контекста браузера, включая `localhost`.
